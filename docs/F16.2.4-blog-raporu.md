## §3. Migration Detayı

### Dosya
`backend/database/migrations/2026_09_24_000044_blog_seed.php` (2,323 satır)

### İçerik
- **4 blog yazısı**: Fiyat Rehberi, Site Bahçesi Kurulum, Restoran ROI, Otel Dış Mekan
- **6 dil**: TR, EN, DE, FR, IT, AR
- **24 çeviri**: Her yazı için 6 dil × 4 yazı = 24 `blog_yazisi_cevirileri` kaydı
- **24 SEO**: Her dil için `seo_verileri` kaydı (`sayfa_tipi='blog'`, `sayfa_kodu` bazlı)
- **Idempotent**: `ON DUPLICATE KEY UPDATE` kullanılmış
- **down()**: seo → ceviri → yazilar sırasında silme

### Bug Düzeltmeleri
1. **`dil_kodu varchar(5)` → `varchar(20)`**: `x-default` hreflang anahtarı (9 karakter) `varchar(5)`'e sığmıyordu.
2. **`sayfa_kodu`/`dil_kodu` swap**: `seoSatirlari()` dizisinde `[referans_id, dil_kodu, sayfa_kodu, ...]` olması `INSERT` cümlesindeki `(sayfa_tipi, referans_id, sayfa_kodu, dil_kodu, ...)` sırasıyla çelişiyordu. SQL sütun sırası `dil_kodu, sayfa_kodu` olarak düzeltildi.

#### Cevaplanan Karar Soruları

**a) ALTER hangi tabloda?**
→ Sadece `blog_yazisi_cevirileri` ve `seo_verileri`. 12 diğer tablo hâlâ `varchar(5)`.

**b) Neden gerekli oldu?**
→ `x-default` (9 karakter) bir **JSON anahtarı** olarak `hreflang_json` içinde kullanılıyor. `dil_kodu` sütununa **asla** değer girilmiyor — tüm `dil_kodu` değerleri `tr/en/de/fr/it/ar` (2-3 karakter). Gerçekten gerekli olan sebep swap bug'tu (`dil_kodu`'na `sayfa_kodu` değeri geliyordu, 32 karakter).

**c) Diğer tablolarda dil_kodu hâlâ varchar(5) mi?**
→ EVET. 12 tablo `varchar(5)` kaldı. Bu tutarlı bir durum — sadece blog tabloları genişletilmiş.

**d) Tutarsızlık var mı? Olası çözümler?**
→ Evet, tutarsızlık var. `ALTER` **migration dosyası `2026_09_24_000044` içinde YOK** — MySQL CLI ile manuel yapıldı (`ALTER TABLE ... MODIFY COLUMN dil_kodu varchar(20)`). Bu, fresh deploy'de migration tekrar çalışınca hata vereceği anlamına gelir.

**Karar Önerisi (L5 onayı bekleniyor):**

| Seçenek | Açıklama | Risk |
|---------|----------|------|
| **A** | `varchar(20)`'ı koru + `ALTER TABLE` cümlesini migration 000044'e ekle | En güvenli. Fresh deploy'de de çalışır. `x-default` future-proof. |
| **B** | `varchar(5)`'e geri al + swap fix'i tut | Minimalist. `x-default` JSON key olarak sorun yok. Ancak `zh-CN` gibi yeni kodlar geldiğinde hata riski. |
| **C** | `varchar(20)`'ı koru + yeni migration 000045 oluştur | Clean ayrım ama 2 migration içeren bir chain oluşur. |

**Seçim:** **A** (tüm dil_kodu tablolarını varchar(20) yap) veya **B** (varchar(5) tut, x-default JSON key kalır).

## Şema Normalizasyonu

**L5 Kararı:** Path A — `varchar(20)` → `varchar(5)` (tüm tablolar tutarlı)

### Gerekçe
- `x-default` yalnızca `hreflang_json` JSON anahtarıdır, `dil_kodu` sütununa değer girilmez
- Tüm 24 çeviri + 24 SEO kaydında `dil_kodu` değerleri: `tr/en/de/fr/it/ar` (2-3 karakter)
- `varchar(20)` gereksiz genişletmeydi; manuel ALTER migration'a dahil edilmemişti (fresh deploy hatası riski)
- Semantik tutarlılık: 14/14 tablo `varchar(5)` olmalı

### Migration: `2026_09_24_000045_dil_kodu_normalize.php`

```php
// up(): varchar(20) → varchar(5)
ALTER TABLE blog_yazisi_cevirileri MODIFY COLUMN dil_kodu VARCHAR(5) COLLATE utf8mb4_unicode_ci NOT NULL;
ALTER TABLE seo_verileri MODIFY COLUMN dil_kodu VARCHAR(5) COLLATE utf8mb4_unicode_ci NOT NULL;

// down(): varchar(5) → varchar(20) (geçici geri alma)
```
